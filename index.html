Why NightLight

为什么需要 NightLight

夜间监控是安防、交通、工业场景中最常见也最容易被忽视的痛点。大量摄像头一到夜间就沦为摆设。

痛点

🌑 夜间可视性差

低照度下画面漆黑、噪点密集，人眼难以辨识车牌、人脸和异常事件。简单亮度拉伸导致过曝和色彩失真。

痛点

📋 多路运维效率低

数十路视频流需逐路检查状态、手动重启故障流、人工记录日志。重复工作耗时且易遗漏告警。

痛点

🧠 缺乏智能辅助

系统只能被动显示，无法主动识别异常、提供诊断建议或执行自动化运维，故障排查全凭经验。

痛点

🔧 系统碎片化

采集、增强、推流、展示由不同厂商系统拼凑，接口不统一、状态不同步、维护成本高。

方案

⚡ AI 实时增强

ONNX Runtime 深度学习推理 + CLAHE 直方图均衡化，GPU 不可用时自动降级到 CPU，确保始终可用。

方案

💬 自然语言调度

LLM Agent 将自然语言转为结构化控制指令，智能诊断故障并提供处置建议，变更操作需审批防误操作。

方案

📊 多路统一管理

3×3 视频墙同时监控多路流，流生命周期一键管理，FPS/延迟/错误率实时展示，Prometheus 全链路可观测。

方案

🔌 端到端整合

Server/Agent/Client 三层解耦，标准化协议通信，Docker 一键部署，从采集到展示一套系统搞定。

Features

核心能力

从低光照采集到 AI 增强再到 RTMP 推流，端到端的实时视频增强解决方案。

🌙

低光照实时增强

基于 ONNX Runtime 的深度学习推理，对低照度复合退化图像进行实时增强，支持降噪、去模糊、亮度提升。

🤖

LLM Agent 智能调度

集成大语言模型 Agent，通过自然语言指令控制视频管线，实现智能化参数调优和场景切换。

📡

RTMP 推流

内置 RTMP 推流模块，增强后的视频可直接推送至直播平台或流媒体服务器。

🖥️

跨平台客户端

基于 Qt/QML + OpenGL 的桌面客户端，支持视频墙展示、实时预览和交互控制。

🐳

Docker 一键部署

提供 Docker Compose 编排，支持 GPU 加速，一条命令启动完整的 Server + Agent 服务。

🔌

模块化架构

Server / Agent / Client 三层解耦，通过 WebSocket + TCP JSON 通信，各组件可独立扩展和替换。

Architecture

Quick Start

快速上手

Docker 一键启动，或手动构建。

Docker 
# 构建并启动 Server + Agent
docker compose up -d

# GPU 加速模式
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d

# 健康检查
curl http://127.0.0.1:19102/health
Manual Build 
# Server
cd Server && cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target ServerMainCoreV2 -j 8

# Client
cd Client && cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target nightlight_client_v1 -j 8
